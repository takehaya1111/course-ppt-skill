# 课程pptskill

这是 **PPT Master 的课程教学定制**。沿用其策划、风格与图像资源、逐页设计、原生导出能力；把课程目标、逐字稿、课堂材料、跨页理解和点击节奏加入这些环节。教学设计纲提出需求，成熟设计流程负责把需求做成画面，不能把上游缩减为导出器，或用固定文字框模板替代设计。

交付是可编辑 PPTX。SVG 是作者中间稿；不以网页、视频或整页截图代替。模型负责教学取舍和构图，程序核对来源、对象、备注、动画及版本；技术通过不能推出专业设计通过。

**主线：课程大纲＋完整口播稿＋可选教学提示 → 本技能的原版策划 → 唯一正式 PPT 设计纲 → 制作与审阅。**口播技能负责讲述内容与必要教学意图，本技能负责屏幕如何承担这些任务。不要要求口播端预先写逐页设计纲；没有额外提示时直接研读原材料，在现有设计纲中记录理解与设计取舍。

## 开始制作

本目录称为“技能目录”。上游完整技能位于 `vendor/ppt-master/skills/ppt-master/`；运行入口为 `scripts/run.mjs`。先按分发包安装说明准备运行环境，再以技能目录的实际绝对路径调用：

```powershell
node <技能目录>/scripts/run.mjs doctor
node <技能目录>/scripts/run.mjs init <本次工程路径>
```

相对工程路径按调用者当前目录解析。使用 `init` 实际返回的目录，不猜命名，不把课程材料写回安装目录。

1. **定位本次材料和范围。**按 [材料到表达](references/material-to-expression.md) 分层读总纲、分纲、本次范围完整口播及必要上下文；核当前版本、认可状态和实际冲突，摘要不能替代全文。确认新作、修订或局部实验，冻结来源副本与哈希，原课程文件保持只读；缺提示不阻断制作，不暗改定稿措辞与讲述顺序。
2. **进入原版策划，加入教学要求。**读 [制作路线](references/ppt-master-route.md) 指定的上游入口和触发分支。依据 [教学定制需求模板](references/teaching-customization-template.md) 把目标、材料与课堂约束写入原版设计文档；按 [课程整体感](references/course-design-continuity.md) 实际读取本课程共享设计依据及认可代表页，记录继承来源、范围和开放项；按 [视觉参照](references/visual-baseline.md) 看优秀内容页，确定专业完成度目标。遇到原文精读、对照、分类、持续关系等任务，按 [教学任务校准](references/teaching-calibration.md) 只选相关的1—2个案例，核规划与成品差别，不能只记作品名称或照套外框。
3. **让设计纲可执行。**按 [课程设计输入](references/course-design-input.md) 写 `design_spec.md`、`spec_lock.md` 和 `course-project.json`。每页明确学生理解变化、语义关系、承担关系的视觉对象、素材需求、原稿对应与点击；页数由教学任务决定。
4. **逐页设计，前段校准。**同一主作者执行原版 `executor-base.md` §2.2 九步，先理解任务与关系，再选择表达，最后写坐标与完整 SVG。按需要实际加载模式、风格、图片、图标、形状和结构工具，参见 [上游复用落点](references/upstream-adaptation-map.md)。允许计算坐标和重复图元；不要先造窄页面生成器，再把整讲挤进它支持的版式。
5. **编译、实际看图、修复并交付。**按 [设计审阅](references/design-review.md) 同时对照原材料与实际跨讲代表页，分开判断内容准确、关系兑现、整套感和专业参照完成度。没有旧讲次参照时如实限制结论；同色或字段齐全不等于整套感。明确未达标时修复，不能降为“清楚、无溢出”后放行。

## 执行顺序

```powershell
node <技能目录>/scripts/run.mjs prepare <工程>
# 计划超过6页：仅前5页完成时检查
node <技能目录>/scripts/run.mjs gate <工程> early
# 按设计审阅文档渲染该次SVG快照、review-pack --early、独立审阅、review-import --early
# 再运行gate early，取得EARLY_REVIEWED后写第6页。6页及以下无需此关卡。
node <技能目录>/scripts/run.mjs build <工程>
node <技能目录>/scripts/run.mjs check <工程> <本次PPTX>
node <技能目录>/scripts/run.mjs states <工程> <本次PPTX>
# 对states生成的每份状态PPTX运行；无点击全套可直接渲染本次PPTX
node <技能目录>/scripts/run.mjs render <工程> <状态PPTX> --backend office
node <技能目录>/scripts/run.mjs review-pack <工程> <实际渲染请求.json>
# 将返回的审阅包和提示派给真正独立上下文，保留宿主指派、返回原始记录
node <技能目录>/scripts/run.mjs review-import <工程> <独立原始报告.json> <宿主记录.json>
node <技能目录>/scripts/run.mjs release-check <工程> <本次PPTX>
```

早期检查是内部校准，不新增教师逐批审批。用户已有委托覆盖的选择继续执行，按上游相应委托分支记录真实决定，不伪造界面确认回执。既有课件修订使用制作路线中的修订入口，不能补造过去未发生的早期检查。

`prepare/build`直接调用原版设计纲与执行锁的格式校验；无版本标记不能再按旧格式略过。逐页作者和审阅均使用原版“实际载体收据”，检查设计纲要求的图文、关系和素材是否落在画面。收据是事实，不是图片配额。`review-pack`只整理冻结事实，原始审阅必须来自实际看图；作者自写`pass/independent:true`、只换姓名、以终态图冒充初态图均不能取得交付通过。宿主不能提供独立上下文时如实保留为自审稿，不能伪造独立记录。

审阅需实际覆盖原版硬规则和软规则，保留适用性、具体观察及未处理问题，不能只填一个空的发现清单。间距以设计纲§V为依据，构图以页面任务为依据；有意非对称不等于对齐错误，标签也不必一律大于正文。详见[设计审阅](references/design-review.md)。程序核覆盖与结论一致性，不能证明模型认真看图，也不能强制绕开本入口的宿主执行技能。

## 教学与设计约束

- **让画面解释。**并列、先后、归属、对应、因果和限制不能只存在于设计纲；用恰当的位置、方向、区域、比例、图像或文字组织兑现。比例需有依据，不能把定性关系画成量化结论。必要的法条条件和主体身份不能因图解简化而消失。
- **整套统一、逐页因内容构图。**从本课程依据继承必要色彩角色、字体层级、材料处理和共同对象，写进原版设计纲与执行锁；同一对象跨页保留身份。共同背景或页脚不能替代内容连续性；构图、形状和图文组合随任务决定。暖纸、墨线、编辑式风格是可选方向，不是所有学科的固定模板。
- **资源按需要落地。**读过模块不等于已吸收；记录“采用哪条方法、用在哪页哪个对象、实际效果怎样”。图片承担材料观察、对象辨认或情境说明时使用；真实照片、艺术作品、教学示意分开标明，生成图不得充当史实或法律证据。原生图表/表格只在真实数据编辑需要时启用。
- **口讲与上屏分工。**完整原稿按来源进入备注，屏幕保留必要任务与证据；引文逐字核对，允许凝练解释文字。默认教师控制的简单点击淡入，常见每页0—3次，按理解步骤调整，不为动画增加空页；不默认视频、旁白或复杂转场。
- **不靠删检查获得通过。**失败在对应环节修复，保留上一产物。不得为了消除错误暗改来源哈希、删必要内容或缩字硬塞。保留完整上游分发、来源与许可。

## 已验证范围

这一制作方式已在三页教学定制试样中完成原生导出、内容核对、实际 WPS 静态渲染及全部有效显隐状态审阅，并获得本次样例的设计认可。它支持继续制作和验证新课程，**尚不能据此宣称整套课程或更换模型后质量稳定**。静态状态检查也不证明实际淡入放映。

记录材料准备、设计、编译、审阅和修复的实际时间；不要把导出用时当成全流程耗时。新增零件或宣称吸收外部能力时再读 [吸收证据](references/absorption-evidence.md)，普通制作不重复全库调研。历史实验及私有课程文件不属于这个独立分发包。
