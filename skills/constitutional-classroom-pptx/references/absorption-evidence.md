# 扩展零件时的吸收证据

只在准备新增、替换或宣称吸收外部能力时读取；普通课件制作不重跑全部调研。

先研究目标成品怎样产生，再决定改造什么。代码工具、模型设计方法和视觉素材是不同零件；不能只拿导出器就声称获得整套设计能力，也不能先锁定窄接口，再只找能塞进接口的功能。

为真正准备使用的零件留下五项短记录：

1. **来源**：项目、固定版本、文件、许可、适用场景。分开原生可编辑、图片封装和网页参考的能力。
2. **效果产生链**：输入经过什么选择、方法、资源或代码，最终产生哪个可见对象或交付行为。README 声称、目录里有源码、读过规则都不能代替实际核读和运行。
3. **改造边界**：保留、增加、替换了什么；被替换机制原本的作用怎样继续完成。教学定制可以深入策划、需求分解、材料、备注和审查，但不能无意削掉原有设计能力。
4. **新内容试用**：用本次许可范围内的新材料实际制作、查看结果和关键行为。复编已有优秀源稿只证明重建，不证明能设计新课。
5. **失效与未知**：记录已发现的失败模式、修复及尚未验证的能力；不为凑清单安装无关项目或运行无意义测试。

状态用“候选、机制已核读、局部工具已运行、课程适配已试用”等准确表述。上一轮的局部验证不会自动升级为整套吸收。证据不足时限缩结论，同时保留已验证的技术成果。

现行上游的具体复用安排见 [上游复用落点](upstream-adaptation-map.md)。普通课件只需记录本次选用模块及其实际落点，不要求重复撰写一份项目调研报告。
