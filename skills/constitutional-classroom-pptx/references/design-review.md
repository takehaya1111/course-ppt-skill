# 从原版逐页审阅到课程交付

沿用固定原版 `vendor/ppt-master/skills/ppt-master/` 的 `workflows/stages/visual-review.md`、`references/visual-review.md`、`executor-base.md` 实际载体复核及选定风格的 Review Focus。作者负责设计，协调者预先渲染，独立上下文按原版逐页格式实际看图。每批至多五页；多批保留各自原始观察，由实际独立审阅者汇总完整报告，不能用程序补写未看的页。课程增加的是原稿含义、教学任务、跨讲共同语言与专业参照判断，不重造一套策划器。

## 先核设计纲，再核实际承载

`prepare/build`直接使用原版 `project_specs.validate_markdown_schema` 检查正式设计纲和执行锁，拒绝缺失版本标记的旧格式跳过路径；自定义模式和风格按原版写实际行为，不强求不存在的外部引用。

原版质量报告的 `carrier_receipt` 记录实际文字、图片、几何和原生形状等使用情况。逐页将它与 §IX 教学任务、资源计划和实际画面对读：有观察材料却未使用、关系被缩成词语排列、选择的表达工具未落地时，回到作者环节修复。统计不能判定美感，也不是每页图片或图形配额；法条对读、短问题等文字页可以合理成立。不能以“克制”“赶时间”笼统解释整讲表达退化。

专业目标在制作前写入原版 §I 或 §V；可沿用已有 Design target / references 段。审阅承接程序从原版文档提取的完整目标，不另设一份目标、不临时改成只有无溢出。实际参照必须有可看的图片，作品名称不等于比较证据。

## 当前文件怎样成为审阅输入

1. 完成 `build/check/states`。有点击时逐份渲染 states 返回的状态 PPTX；全套无点击时直接渲染当前成品。
2. 调用 `render <工程> <状态PPTX> --backend office`。命令保存源副本、实际页号、PNG、文件哈希、软件名称和原始渲染报告；只导出图片不会获得设计通过。没有目标软件时可明确使用 `--backend libreoffice`，记录替代软件边界，不静默切换。不可用 SVG 预览冒充最终 PPTX。
3. 将程序返回的真实字段写入请求，执行 `review-pack <工程> <request.json>`。请求格式见 [review-request.schema.json](review-request.schema.json)，包含真实作者/审阅上下文、参照图，以及各有效 `slide/state` 的 `imagePath/imageHash/renderManifestPath/renderManifestHash`；设计目标可省略由程序提取，若提供须全文一致；有点击时附本次 `states` 命令登记的 `stateReportPath`，不接受改写报告。每页只登记 `0..clicks`，重复终态不另算。未知的历史作者可如实写外部作者身份，不编造旧会话编号。
4. 命令核“状态源文件—实际页号—图片”的对应，冻结材料、备注、设计纲、执行锁、参照、原版载体收据和风格观察项，输出只有事实的审阅包及提示。它不生成观看声明或通过结论。两个状态确实相同时允许 PNG 相同；不能把终态渲染记录配给不同的状态源文件。

无图像来源凭据的旧审阅不能自动升级。修改原稿、素材、页面或目标后，按实际影响重新制作、渲染、派发；不能只换哈希消除错误。

## 独立审阅者实际看什么

先读冻结材料及来源定位，再看全部有效状态和实际参照图。分开回答：

- **内容和时机**：主张、主体、关系、条件、引文身份是否正确；拆合页及点击是否提前揭示答案或改变定稿顺序。完整备注只是支持定位，不能替代阅读。
- **画面兑现**：并列、先后、归属、对应、因果、限制是否由适当位置、方向、区域、图像或文字组织解释；图形是否添加原稿没有的量化、对称、边界或阶段含义。
- **整套感**：共同对象能否辨认，局部能否回到总图；将当前页与实际跨讲代表页一起看，核字体/色彩角色、材料处理和持续对象。没有既有课参照就限制结论范围，同色不是整套感证明。
- **专业完成度**：逐页对照匹配的优秀内容页，比较信息组织、视觉层级和主要解释对象；不能把无溢出、字段齐全或几个箭头当作达到参照。纯文字确实更能完成任务时，说明理由。

原始报告格式见 [raw-review.schema.json](raw-review.schema.json)。每个状态保留原版 `status/findings/needs_human_items/design_intent_check`，其中 `spec_says` 引用该页 §IX 原文，`render_delivers` 和 `note` 写实际判断；另写 `pageJob/relationships/realization/observations`。每页末态补载体复核、实际参照比较和适用风格检查，其他状态不重复长篇美感说明，但必须真正看图。

整套报告记录实际 `deckReview`、`designTarget`、未解决问题与限制。未达到既定目标写 `not_met`，总状态失败。明确缺陷不得靠改成建议或填空数组放行；审阅是只读的，不能写“已修复”绕过作者修复后的重新渲染。实际看图之后可用程序整理记录，禁止由程序生成观察或预填通过。

## 指派与收录

协调者先建立真正与作者隔离的上下文，再将返回的包及提示派发。保存宿主实际指派和返回原始记录；原始指派须关联上下文、调用和审阅包哈希，原始返回须关联该上下文和原始报告哈希。格式见 [review-dispatch.schema.json](review-dispatch.schema.json)。只换姓名、启动一个脚本或手写另一编号不构成独立审阅。

```powershell
node <技能目录>/scripts/run.mjs review-import <工程> <原始报告.json> <宿主记录.json>
node <技能目录>/scripts/run.mjs release-check <工程> <本次PPTX>
```

导入仅生成引用原始文件的 [design-review.schema.json](design-review.schema.json) 包装记录，不替审阅者判断。交付检查重新核文件绑定、全部状态、目标原文、独立上下文、实际指派/返回和逐页结论。缺失或失败均不能声称已完成。宿主无独立上下文能力时可继续作者自审并保留草稿，但不能冒充独立验收；可由真实第二会话或人员补审。

这些记录检查一致性，不能证明模型真的看懂了图片，也不能抵抗同权限程序伪造全部本地文件；不宣称所有模型审美稳定。用户认可、课堂效果、真实淡入放映单独记载，静态显隐检查不证明播放。

## 前五页同样走原版路径

超过六页时，仅有前五页 SVG 就运行 `gate <工程> early`，在其独立快照工程启动原版实时预览，再调用 `render-svg <工程> <快照工程>`；沿用原版 `visual_review.render_pages` 的真实预览及画布信息。不能拿后改稿冒充快照。

请求引用上述五页各 state0 的实际渲染记录；`review-pack` 和 `review-import` 加 `--early`。实际审阅完成后，在仍只有五页时再次调用 `gate early`，取得 EARLY_REVIEWED 再写第六页。这是内部校准，不新增教师逐批审批，也不能事后隐藏后页补造历史。发现方法错误先修复，不带着错误批量铺开。
