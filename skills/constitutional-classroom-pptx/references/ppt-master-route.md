# 原版设计能力上的教学定制路线

## 固定组件与入口

上游位于技能目录内 `vendor/ppt-master/skills/ppt-master/`，固定提交 `ca04346de145ed6462ddf34682848e71df5e20a2`，PPT Master 6.7.0，保留完整分发和许可。课程适配入口是本技能根目录的 `scripts/run.mjs`，不是上游内部脚本目录。以下上游文件名都相对此上游目录；不要误读另一份未经固定的安装。

先运行 `doctor`，按安装说明处理明确缺失的依赖；不每次重新下载上游或重建官方样例。运行环境与内容工程分开，工程路径按调用者当前目录解析。缺少能力时报告具体原因，不删检查、不悄悄换导出路线。

分发包保留上游共享规则的相对目录关系，按原链接读取 `vendor/ppt-master/docs/rules/`。上游 `update_repo.py` 面向其原仓库，不能用于更新此定制技能；定制包更新以本项目发布版本为准。

## 进入原版策划

1. 初始化独立工程，按[材料到表达](material-to-expression.md)分层读当前总纲、分纲、完整成稿和上下文，冻结实际来源。按[课程整体感](course-design-continuity.md)读本课程设计依据及认可代表页，记录实际来源/版本/认可范围；课程原件保持只读。
2. 读上游 `SKILL.md`、`workflows/routing.md` 和普通 `workflows/generate-pptx.md`，按其策划阶段读 `references/strategist.md`、`plan-core.md` 及触发的规划参考，运行上游要求的归属检查。用户已委托的选择使用真实委托分支，不重复审批或伪造确认回执。
3. 用 [教学定制需求模板](teaching-customization-template.md) 把理解变化、原稿分工、素材身份、投影与点击需要送入策划。模板是需求层，不是第二套封闭设计器，也不要求另建一份与设计纲冲突的文件。
4. 实际看 [视觉参照](visual-baseline.md) 中匹配的优秀内容页。按上游方案选择机制形成方向；不能用“只改背景和字体”替代对构图方法的判断。确定模式、视觉风格及必要图像语言后，实际读取对应文件，并写清采用行为。
5. 按 [课程设计输入](course-design-input.md) 编排 `design_spec.md`、`spec_lock.md` 与 `course-project.json`。完成本阶段需要的素材取得或准备，保留图源；不能让纸面写了“有图”而制作时无声改成文字框。
6. 调用 `prepare <工程>`。它直接运行原版设计纲及执行锁的版本化格式校验，再核计划、来源、素材并运行官方字体校准，不要求全套 SVG 和备注已经存在。缺少版本标记不会按旧格式跳过。主要字级、风格或页计划改变时更新计划并重新准备；重新准备后须重新构建，不能把新记录冒充旧构建历史。

## 按需要用成熟零件

遵照上游规定的完整常驻上下文，包含 `executor-base.md`、`shared-standards-core.md`、`semantic-svg.md`、`preset-shape-vocabulary.md`，以及本次选定的模式与视觉风格文件。按内容需要继续加载图片、关系结构、原生形状、图表、表格等分支，详见 [上游复用落点](upstream-adaptation-map.md)。不要按自己最容易编写的 SVG 元素倒推教学表达。

逐页执行上游 `executor-base.md` §2.2 九步；现有页卡和作者记录保留简短可审查决定：学生要理解什么 → 内容有何关系/条件 → 屏幕需让学生看见什么 → 实际选用的图文怎样解释 → 与前后页及课程代表页怎样相连。不输出内部推理过程，不另建九步表或第二套页面生成流程。

由同一主作者连续直接编写 `svg_output/<stem>.svg`。允许辅助程序计算坐标、生成重复图元、调用原生预设或布尔工具。作者仍需根据每页任务调整完整构图，不能批量套用几种文字框后宣称完成原版设计流程。

- 关系页核主体、方向、区域、比较基准和限制。并列不得变成先后，内部部门不得变成新的对外主体。
- 图片页先决定观察任务、完整/裁切边界和说明位置；图片身份与可编辑注解分开。
- 文字页可以用逐字条文、短问题或对读完成恰当任务，但须说明组织方式怎样帮助理解。
- 共同对象保持身份，局部展开能回到总图；不同任务的构图应有理由地变化。每五页重读设计锁，不逐图元重装环境或重复所有工具。

## 前五页内部校准

计划超过六页时，现场仅有前五页 SVG 后运行：

```powershell
node <技能目录>/scripts/run.mjs gate <工程> early
```

它复用官方早期检查并保存源稿、素材与报告快照，此时不要求完整备注。按[设计审阅](design-review.md)调用 `render-svg`、`review-pack --early`，将对应预览及实际参照派给独立上下文；保留原版逐页观察后，以 `review-import --early` 收录真实原始报告及宿主指派、返回记录。不得手写独立通过包装文件。发现方法、关系或专业完成度问题，先修再审。

仍只有五页时再次运行同一命令收录审阅，取得 `EARLY_REVIEWED` 再写第六页。不能先画整套，再隐藏后续页面补造早期历史；也不要求教师再次批准。六页及以下无需此机械关卡，但保留准备、逐页设计与最终审阅。

可用上游 `scripts/svg_editor/server.py <工程> --live --daemon --no-browser` 预览。早期实看须对应记录中的独立快照，不能用后来改写的源稿冒充旧状态。

## 编译与实际成品审阅

1. 完成逐页同名备注与 `animations.json`。完整口播进备注，原稿与上屏分工明确；组数可以大于点击数，无动画页允许零次。若维护总备注，它须与逐页稿一致。
2. `build <工程>` 核完整输入、适用阶段记录、官方最终检查和原生导出，再回读真实文件。输入指纹与 PPTX 哈希绑定。真实图表、表格只按契约明确需要启用，图片字节按实际登记核对。
3. 按原版 `executor-base.md` 的实际载体复核，读取官方质量报告 `carrier_receipt`，对照设计纲检查主体、关系、素材作用是否兑现。对象计数只用于找异常，不是审美分数或图片配额；不能用“克制”掩盖整套退化成中性文字排列。
4. `states <工程> <PPTX>` 按真实动画结构生成静态显隐副本。使用实际目标软件渲染最终文件与有效状态；独立审阅者查看所有页及各页 `0..clicks` 的状态，重复终态不额外算新状态。
5. 使用 `render` 保存每个状态的真实源文件、页号与PNG映射，再按 [设计审阅](design-review.md) 的 `review-pack → 独立上下文原始审阅 → review-import` 同时回查原稿及实际跨讲/专业参照，最后 `release-check <工程> <PPTX>`。缺失、失败、过期或设计目标未达成均不能交付为完成；机械通过不自动生成设计认可或跨讲整体感结论。

Windows 通过 `render --backend office` 使用现有 WPS/PowerPoint，识别实际软件；已有演示程序只借用接口打开独立只读副本，不修改或关闭用户文稿，结束只关闭本次打开的副本。`--backend libreoffice` 使用独立配置目录和现成 PDF 渲染工具，明确记录替代软件边界。源稿预览、PPTX 实显、静态显隐和真实淡入放映是不同证据。

## 已有课件修订

不为旧工程补造从未发生的早期检查。新建修订工程，保存 `revision-scope.json`：`{baselineProject:旧工程绝对路径, reason:本次修订理由, slides:[需改页stem...]}`，再调用 `prepare <新工程> --revision-of <基线PPTX>`。基线需有可核原工程和实际产物记录，不能拿另一套样例冒充。

当前修订分支保留页序；增删或重排按新的页计划处理。重新构建后旧审阅不能原样通过，需实际复核当前产物；差量证据可帮助检查，但不自动代填未变页的观看结论。

## 时间与结论边界

记录材料、设计、编译、审阅和修复的真实时间。主要检查时点是制作前、前五页和最终，具体失败再定向检查。机械脚本用时不等于新内容制作耗时。

上游机制已理解、工具已运行、新课效果通过、教师认可和跨模型稳定是不同结论；一项证据不能替代另一项。小样通过不自动证明整讲稳定。
