# 教学定制需求模板

把下列信息编入上游 `design_spec.md` 相应章节；它是内容需求的基础模板，不是新增一份平行大纲，也不是规定页面坐标的模板。先按[材料到表达](material-to-expression.md)读懂并提炼，再填写本次需要的内容，已有用户决定直接继承。共同栏目只是承载决定，整套感须按[课程整体感](course-design-continuity.md)继承真实依据并看图核对。

## 本次教学委托

| 要素 | 需要写明 |
| --- | --- |
| 本次范围 | 哪一讲、哪一段，或修订哪些页；不自动扩大成整门课 |
| 当前材料 | 总纲、分纲、本次范围完整口播与必要前后文、真实材料及版本；缺失范围如实记，可选教学提示不代替全文 |
| 学生起点与结果 | 已经知道什么，本次结束应能解释、辨认或应用什么 |
| 课堂使用 | 教师主讲或学生自读、投影环境、时长及必要互动 |
| 原稿与屏幕分工 | 哪些话口讲，哪些证据/关系必须上屏，哪些原文不可改；原稿何时提问、何时揭示，画面怎样配合 |
| 整套身份 | 课程设计依据的来源版本、认可范围与实际看过的代表页；继承的颜色/字体角色、材料处理、必要定位和连续对象；本讲开放项与必要变化 |
| 专业参照 | 具体内容页、实际看过的表达方法、本次可检查的完成度准则 |
| 交付 | 可编辑 PPTX、备注、点击方式；本次是否需要真实图表或表格 |

## 每页页卡：写入内容纲

- **学生理解变化**：从什么认识到什么认识。不要只写知识点名称。
- **页面任务与一句主张**：这一页让学生观察、区分、理解或判断什么。
- **来源与备注**：对应讲稿段落、原文材料位置、逐字引文、必须保留的条件。拆合页后仍标清完整原段的归档位置；不把一段一页当规则。
- **语义关系**：谁与谁并列、先后、归属、对应、因果或受何限制；明确哪些关系不成立。
- **画面承担**：哪些对象、关系、证据和限制需要学生同场看见，什么必须保持、什么发生变化。可以提出宏观表达参考；实际图文组合、形状和坐标由作者按原版九步决定。文字组织确实能完成任务时不强加图形；需要看见的关系不能只留在备注中。
- **构图与连续对象**：本页焦点、阅读路径；承接前页什么，后页将展开什么。构图可因内容调整。
- **素材和零件需求**：需要真实图、生成示意、图标、原生形状、关系结构、表格或数据图中的哪些；先检查上游现有资源与工具，再决定改造。没有需求不凑齐所有类型。
- **素材作用与身份**：让学生看哪里、证明什么/不证明什么、能否裁切；真实材料来源与许可另记。
- **点击与常驻**：初始可见什么，每次点击解决哪一步理解，是否会提前泄露原稿留给学生判断的内容。课堂材料通常先可见，结论按需揭示。
- **验收观察**：正确实现时，审阅者应在页面上看见什么；容易误读的地方是什么。

页卡中保留材料定位，简短说明哪些属于原材料要求、哪些是PPT侧设计判断。没有额外教学提示时从完整稿恢复这些信息，不要求上游先写一份逐页纲。实际冲突按[课程设计输入](course-design-input.md)处理。

## 一条需求怎样落地

以“比较两种方式，共同条件不变”为通用示意：先核材料是否真的支持并列；再选择能同时显示两种方式和共同条件的构图。共同条件可以是共享区域或对应字段，方式可以是路径、图像或文字对读，不预设必须两张卡片。对照时确认共享条件实际可见，顺序、箭头和视觉轻重不会暗示一个方式必须先于另一个。

这只是说明从语义到画面的转换，不是可批量填词的版式。

## 设计定稿前的简短核对

对每项选用资源留下“来源模块 → 采用行为 → 页面对象/位置”的一句记录。检查共同设计语言及适用角色是否进入执行锁；构图与专业参照目标留在设计纲相应段落，不新增不受上游支持的锁字段。核素材已取得或有明确替代方案。完成设计纲才准备制作，不能先编译一套窄模板，再倒填教学设计理由。
